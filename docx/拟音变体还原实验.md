# 拟音变体还原实验方案

## 一、项目总体思路

本项目面向内容审核场景下的**拟音变体还原**问题，目标是将经过谐音、数字、英文、拼音、缩写、中英混写等方式变换后的网络文本，恢复为其对应的标准表达。例如，将 `Delay no more`、`丢雷楼谋` 等变体恢复为“吊你老母”，将 `4你全家` 恢复为“死你全家”。

经过前期讨论，本项目确定的核心技术路线是：**使用规则和现有语言工具，将变体文本转换为尽可能模拟人类阅读时产生的读音序列，并统一表示为 IPA 音素序列；随后利用构造得到的“变体文本—音素序列—标准文本”数据，对预训练 Seq2Seq 模型进行针对性微调，使模型学习从语音表征中恢复标准文本。** 该方案的核心假设是，人类在理解拟音变体时，往往会先根据文字形式在脑中形成近似读音，再通过读音联想到目标词。因此，IPA 可以作为连接“变体表面形式”和“标准文本”的中间表征。这里需要注意，IPA 本身并不是最终任务目标，而是用于显式提供语音信息，从而验证“加入语音表征是否能够提升拟音变体还原能力”。

与直接依赖规则库或期待通用大模型零样本完成还原不同，本方案希望通过定向训练使模型学习更加一般性的**“表面形式 → 读音模式 → 标准表达”**映射关系。因此，除了验证模型对训练集中已出现变体的恢复能力外，还需要重点验证其对训练阶段未出现、但具有相似发音规律的新型变体是否具有泛化能力。

## 二、实验实施步骤

### 2.1 数据准备与音素转换

第一阶段的重点是构建高质量的拟音还原训练数据，该环节将直接影响后续模型训练效果。首先整理需要恢复的标准表达，形成核心目标词表，例如“吊你老母”“死你全家”“操你妈”等。该词表主要用于训练数据构造和实验评估，并不意味着最终模型只能恢复词表中的表达。

在此基础上，为每个标准表达收集真实网络中的变体，并结合规则进行自动扩展，覆盖汉字谐音、英文谐音、拼音、数字、英文字母缩写、中英混写以及不同空格、大小写和标点形式等。例如，围绕“吊你老母”可以构造 `丢雷楼谋`、`Delay no more`、`dlnm`、`diu nei lo mo` 等不同形式。数据构造时应尽量覆盖不同的变体生成机制，而不是简单增加同一种规则产生的样本数量。

随后利用 `g2p-en`、`pypinyin`、中文 G2P 工具以及自定义规则，将不同形式的变体转换为**模拟人类阅读该变体时可能产生的音素序列**，并进一步统一为 IPA 表示。例如，`Delay no more` 可以转换为近似 `/dɪˈleɪ noʊ mɔːr/` 的音素序列。需要特别注意的是，机器工具输出的标准发音并不一定等同于人类看到网络变体后的实际“脑内读音”，尤其是英文、数字、缩写和中英混写等情况，因此需要通过人工抽样检查和规则修正，确保生成的音素序列尽可能符合真实的拟音认知过程。

最终构建结构化的三元训练数据：

```text
(variant_text, ipa, canonical_text)
```

例如：

```text
("Delay no more", "/dɪˈleɪ noʊ mɔːr/", "吊你老母")
```

第一轮实验建议先准备 **5,000～10,000 条高质量数据**，优先验证方法有效性，而不是一开始追求大规模数据。

### 2.2 模型微调

第二阶段的目标是利用上述数据训练一个专门用于拟音变体还原的模型。第一版实验建议选择 **mT5-base** 作为基础模型。mT5 是多语言 Seq2Seq 模型，能够处理“输入序列 → 输出文本”的任务形式，同时已有 Phoneme-to-Grapheme 相关工作验证了此类模型用于音素到文本转换的可行性，因此适合作为本项目的初始实验模型。

实验中建议不要只训练单一模型，而是至少设置以下三个实验条件：

```text
Baseline：     变体文本 → 标准文本
Phoneme：      IPA → 标准文本
Ours：         变体文本 + IPA → 标准文本
```

其中，第一组用于衡量模型仅依靠文本本身进行恢复的能力，第二组用于验证 IPA 到标准文本的基本映射能力，第三组则是本项目的核心方案，用于验证在保留原始变体文本的同时显式加入 IPA 信息，是否能够进一步提升恢复效果。这样可以避免最终只能得到“模型能够完成任务”的结论，而能够进一步判断**语音信息本身是否真正带来了增益**。

模型训练可以参考《LLM-based Phoneme-to-Grapheme》相关工作以及 CAT 工具包（`thu-spmi/CAT`）中的 LLM-P2G 实现，将数据转换为标准 Seq2Seq 微调格式。第一轮实验不建议过早引入复杂的训练策略，可以先采用标准监督微调验证核心路线。参数高效微调、对比学习、IPA dropout、hard negative 等方法可以放到后续优化阶段。

### 2.3 评估与泛化实验

第三阶段重点验证模型是否真正学习到了拟音规律，而不是简单记忆训练集中的变体。测试集需要进行严格的**变体级别隔离**。例如训练集中出现 `丢雷楼谋 → 吊你老母`，测试集中可以使用训练阶段未出现过的 `Delay no more`、`d1n m`、`diu nei lo mo` 等形式。只有保证具体变体没有出现在训练集中，才能真正评价模型对新型拟音变体的泛化能力。

评估可以进一步划分为三类。第一类是 **Seen Canonical + Unseen Variant**，即标准表达在训练集中出现过，但测试时使用完全不同的新变体，用于评价变体泛化能力；第二类是 **Unseen Canonical**，即测试标准表达本身也没有出现在训练集中，用于进一步观察模型是否学习到了更一般性的语音到汉字映射规律；第三类是 **Cross-type Variant**，训练阶段主要使用某一类变体，例如汉字谐音，而测试阶段加入英文、数字、拼音、字母或中英混写等不同类型的变体，用于评价模型跨变体类型的泛化能力。

主要评价指标采用 **Exact Match Accuracy**，即模型输出与标准文本完全一致的比例，同时可以辅助统计 Character-level Accuracy、CER 和 Top-k Recovery Accuracy。对于本项目而言，Exact Match 是最核心的指标，因为最终目标是准确恢复完整的标准表达，而不仅仅是恢复其中部分字符。

### 2.4 错误分析与方案迭代

如果第一轮实验效果不理想，需要将错误拆分为“变体文本 → IPA”和“IPA → 标准文本”两个环节进行定位。如果变体本身转换得到的 IPA 与人类实际阅读方式存在明显偏差，则问题主要出现在音素构造环节，需要进一步优化数字归一化、英文归一化、缩写展开、中文 G2P 以及中英混写等规则；如果 IPA 已经能够较好地反映变体的实际读音，但模型仍然无法恢复标准文本，则说明主要问题在于模型的音素到汉字映射能力，此时可以进一步增加训练数据、调整模型或训练策略，或者引入候选生成和语言模型约束。

同时需要关注另一种非常重要的结果：如果仅使用原始变体文本的模型已经取得很高的效果，而加入 IPA 后没有明显提升，则说明通用语言模型本身已经能够从文本表面形式中隐式推断语音信息，此时显式 IPA 的价值有限。相反，如果 `Text → Canonical` 与 `Text + IPA → Canonical` 之间存在稳定且显著的性能差距，则能够较有力地证明**显式语音表征确实能够帮助模型理解拟音变体**。

## 三、第一版训练方案：Full Fine-Tuning

第一轮实验建议采用**全参数微调（Full Fine-Tuning）**，主要目的是尽可能验证方法本身的效果上限，而不是优先考虑部署成本。mT5-base 约有 5.8 亿参数，模型权重约 2.2GB，但全参数训练还需要额外保存梯度、优化器状态以及训练过程中的中间激活，因此实际显存需求会显著高于模型权重大小。

硬件方面，**1 张 H100 80GB 显卡可以满足第一版实验需求**。24GB 级别显卡也可以尝试运行，但需要结合较小的 batch size、gradient accumulation、mixed precision、gradient checkpointing 等方式控制显存。考虑到第一轮数据规模仅为 5,000～10,000 条，暂时没有必要为了降低显存而过早引入 LoRA 或 QLoRA；后续如果需要扩大数据规模、进行大量实验或考虑实际部署，再将参数高效微调作为优化方案。

训练时间取决于数据规模、序列长度、batch size、训练轮数和硬件配置，因此不建议将固定的“100 epoch、2 小时”等数字作为正式方案中的确定结论。可以先以较小规模实验测量单 epoch 实际耗时，再据此估算完整训练成本。若按 H100 实例约 **$2～4/小时** 的市场价格进行粗略估算，一次数小时级别的训练成本大致处于 **10～20 美元量级**，具体成本仍取决于实际云平台价格和实验次数。

## 四、MVP 实验目标

第一版 MVP 不需要一次性实现完整的拟音还原系统，而应优先回答三个核心问题：第一，**显式加入 IPA 是否能够提升变体文本的标准表达恢复能力**；第二，**模型能否泛化到训练集中没有出现过的新型拟音变体**；第三，**最终错误主要来源于音素构造问题，还是模型本身的还原能力不足**。

因此，第一轮实验可以收敛为一个最小闭环：

```text
变体文本
   ↓
规则 / G2P / 文本归一化
   ↓
模拟人类读音
   ↓
IPA 音素序列
   ↓
mT5-base
   ↓
标准文本
```

并以以下三个模型作为核心对照：

```text
Text → Canonical
IPA → Canonical
Text + IPA → Canonical
```

如果实验能够证明 `Text + IPA → Canonical` 在严格的未见变体测试集上稳定优于文本 Baseline，则说明“**显式语音表征辅助拟音变体还原**”这一核心路线具有进一步研究和工程化的价值；在此基础上，再逐步扩大数据规模、优化 IPA 构造方式、探索更适合的模型结构和训练策略。
