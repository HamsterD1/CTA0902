如果目标是**最快开启最小可行实验（MVP）**，我不建议一开始就做 5,000～10,000 条。你现在首先要验证的是“**IPA 是否真的能帮助拟音还原**”，所以数据量应该足够训练出一个有意义的模型，同时又方便快速人工检查和迭代。

我建议第一轮直接做 **2,000～3,000 条**，其中：

| 数据     |        建议规模 | 用途       |
| ------ | ----------: | -------- |
| 训练集    |       2,000 | 训练 mT5   |
| 验证集    |         300 | 调参、观察过拟合 |
| 测试集    |         500 | 最终评估     |
| **总计** | **2,800 条** | 第一轮 MVP  |

但这里有一个比总数量**更重要的要求**：测试集不能简单随机切分。你真正想验证的是**未见变体泛化**，所以建议测试集专门构造一批训练中没有出现过的变体。

例如：

```text
训练：
丢雷楼谋 → 吊你老母
diu lei lou mou → 吊你老母
```

测试：

```text
Delay no more → 吊你老母
d1n m → 吊你老母
diu nei lo mo → 吊你老母
```

这样 500 条测试数据才真正有意义。

### 我更推荐的 MVP 数据结构

如果你目前已经有一批标准词，可以先选 **100～300 个 canonical expressions**，每个标准表达构造约 **10～20 个不同变体**：

```text
300 个标准表达
×
10 个变体
≈
3,000 条
```

然后按照**canonical expression 和 variant type 分层划分**，而不是简单随机划分。

第一轮甚至可以进一步压缩到：

```text
1,000 train
200 val
300 test
= 1,500 条
```

如果只是为了确认**代码能不能跑通、mT5 能不能学会这个任务**，这个规模就够了。

所以我建议你的实际执行顺序是：

```text
第一轮 Smoke Test
1,500 条
↓
确认数据格式、IPA输入、mT5训练、推理全部跑通
↓
第二轮 MVP
~3,000 条
↓
正式比较
Text → Canonical
vs
IPA → Canonical
vs
Text + IPA → Canonical
↓
如果有效
扩大到 10k、50k+
```

**不要一开始就上 1 万甚至 10 万。**你现在最需要得到的不是一个高分模型，而是一个非常明确的实验结论：**“加入显式 IPA 后，模型在 Unseen Variant 上是否比纯文本 Baseline 更强。”**只要这个结论成立，后面扩数据才有意义。
